Automation and workflows

Automation pipelines react to GitHub and Jira events across all your projects. Workflows run a series of agent steps in one session.

Automation pipelines

Open Automation from the sidebar. A pipeline has a trigger, filters and actions.

Triggers

  • Pull request opened, ready for review, new commits, CI passed or failed, review requested, approved, changes requested, merge conflict, merged or closed.
  • A Jira ticket newly matches a JQL query, or changes status.
  • Manual run.

Filters

Author, branches, labels, title, draft state, CI and review status, mergeability, size, changed paths, linked Jira project, status, type and priority, and time windows.

Actions

GitHubApprove (once per commit), request changes, comment, add or remove labels, request reviewers, assign, enable auto-merge, merge, close, update branch, rerun failed checks, mark ready for review.
JiraTransition, set Fix Version, comment, assign, label.

Use a dry run on a sample event to check a pipeline before you turn it on. A project's older merge-transition setting is converted to a pipeline automatically.

Pipelines run on the regular polling cycle. Turn on Forward webhooks to automations in Settings → Integrations (needs the gh webhook extension) to react to GitHub events immediately.

Workflows

A workflow is an ordered list of agent steps saved on a project. Each step has a prompt for Claude Code or Codex and a goal that Cascade checks when the agent finishes its turn.

Prompts can use these placeholders:

{url} {key} {pr} {branch} {repo} {worktree} {workspace}

Run and stop a workflow from its session and follow each step's progress. Workflows need agent hooks, installed from Settings → Integrations → Workflow hooks.
