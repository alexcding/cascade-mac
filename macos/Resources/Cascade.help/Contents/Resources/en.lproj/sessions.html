Cascade Help

Sessions and worktrees

A session is one task: a git worktree, the agent working in it, and the page it was started from.

Start a session

  1. Choose File → New Session… (⌘N).
  2. Type a branch name, or paste a GitHub pull request or Jira ticket URL.
  3. Pick the base branch and the agent: Claude, Codex or Shell only.

Cascade creates a worktree for the task and opens a terminal beside its page. You can also right-click a pull request or ticket anywhere in Cascade and start a session on it.

Creating a worktree never waits on the network. Cascade uses what your checkout already has, unless you turn on Always fetch before creating worktrees in Settings → Worktrees.

Working with the agent

  • Use the session toolbar to switch model and effort presets. ⌘D cycles to the next model.
  • Compact or clear the agent's conversation from the toolbar.
  • Click a stopped session to resume it where it left off.
  • Restart stops the shell and resumes the saved agent conversation.
  • Right-click a session in the sidebar to rename it.
  • If an agent will not stop, Cascade detaches it instead of leaving the session stuck.

Open in another app

Open a session's worktree in Xcode, VS Code, Cursor, Windsurf, Zed, IntelliJ IDEA, WebStorm, Android Studio or your own editor command, and in Fork, Tower, Sourcetree, GitHub Desktop or your own Git client command.

For Xcode, Cascade resolves Swift packages in the background before the worktree opens, so the first build does not stall. It deletes that worktree's DerivedData when the worktree is removed.

Remove a session

Cascade previews what would be lost before removing a session. Discarding uncommitted changes needs its own confirmation. Turn on Delete merged branch in Settings → Worktrees to clean up the branch as well.
